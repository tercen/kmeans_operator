# kmeans_rust_operator — maintenance guide

Rust port of the R `kmeans_operator` in this repository (the R operator is
the parity reference and must not change). Built 2026-09-23 by the
sci-operators fleet per `tercen/skills` → `create-rust-operator`; follow that
skill for anything it covers that this file does not.

## Architecture (one line per file)

| file | role |
|---|---|
| `src/main.rs` | production entry: `--taskId/--serviceUri/--token` → env → `run()` |
| `src/bin/dev.rs` | dev entry: `--workflowId/--stepId` against Studio |
| `src/lib.rs` | `run()/run_dev()`: client, context, gather → kmeans → result → upload |
| `src/context.rs` | builds the context from the task alone (not `ProductionContext`, which fails on unsaved workflow steps) |
| `src/chunked.rs` | bounded chunked reads of the cell table, counted against `Schema.nRows` (never `stream_table_chunked`: it only stops on a zero-byte chunk) |
| `src/input.rs` | the streaming gather — sums + counts into dense buffers; `fold_chunk` is the pure, unit-tested acast semantics |
| `src/kmns.rs` | Hartigan–Wong engine: statement-for-statement transliteration of R's `kmns.f` (`KMNS`/`OPTRA`/`QTRAN`) |
| `src/kmeans.rs` | the R `kmeans()` wrapper: `sample.int` init, duplicate-row re-sampling, `nstart`, `k == 1`, error mapping |
| `src/rng.rs` | R's Mersenne–Twister + `set.seed` scrambling + rejection-sampler `sample.int` (from the clusterx lane, validated draw-for-draw) |
| `src/output.rs` | result TSON: `.ci` + `<namespace>.cluster` (labels 1-based, like R) |
| `src/upload.rs` | `save_table` equivalent: stream the result file into `FileService.upload` |
| `src/progress.rs` | progress/log events in fixed percent bands |
| `src/props.rs` | property parsing (numbers as f64, then truncate — the UI writes `"2.0"`) |
| `src/tson.rs` | the TSON writer for the result |

## Crosstab contract

Rows = variables, columns = observations, y = measurement; output is one
`cluster` label per observation column on `.ci` (per-column model). The
manifest (`operator.json`) declares exactly the R operator's spec: join on
the `Observation` pair, one `cluster` string attribute.

## Streaming: the memory pay-off (why this port exists)

R loads the entire long-format cell table and gathers it with
`reshape2::acast`. This port:

1. reads the cell table in chunks of 200 000 cells (`input::CHUNK`), bounded
   by `Schema.nRows` from the qt schema;
2. folds each chunk into `sums: Vec<f64>` (8 B/cell) and
   `counts: Vec<u32>` (4 B/cell), sized from the **row/column factor
   schemas** (`column_hash`/`row_hash` — the task carries them, no workflow
   fetch needed), and validates every `.ri`/`.ci` against them;
3. computes the mean in place over the sums buffer, frees the counts;
4. runs Hartigan–Wong on that buffer (row-major, one row per observation).

No pass ever holds the cell table whole: peak working set is 12 B/cell plus
one chunk during the gather, then the 8 B/cell matrix during the fit. If the
factor schemas are unavailable the gather falls back to a one-pass map of
observed cells (peak ~50 B/cell) — correctness is identical, only the
booking is worse.

Measured (`tests/memory.rs`, release build, jemalloc with the worker's
`MALLOC_CONF`, 10 M cells / 2 000 000 × 5, 2026-09-23, this machine):

- peak RSS 126 716 kB (**123 MB** ≈ 12.4 B/cell), of which the gather peak is
  119 880 kB; the Hartigan–Wong fit itself adds ~7 MB over the matrix and
  takes 0.4 s. The production run adds one read chunk (~5 MB) and the
  tokio/tonic runtime to this.
- the booking in `memory_model.json` is 2·10⁻⁵ MB/cell + 150 MB offset —
  425 MB booked where 10 M cells measured 123 MB + runtime; ~3× headroom.

Refit from `stats_d_actual_ram_peak` in the task meta once there are real
runs on the platform.

## Parity target: bitwise

- Fixtures in `tests/parity/` are generated by the **R reference itself**
  (`generate_goldens.R`, R 4.3.3): 10 cases over the operator's own test1
  input, iris, seeded synthetic data, and data with duplicate rows; raw
  `sample.int` draws in `sample_int.csv`.
- `tests/parity.rs` asserts labels exactly, centres and per-cluster wss
  bitwise (`to_bits`), iteration count and `ifault` equal, warnings
  consistent.
- The engine (`kmns.rs`) preserves R's arithmetic order, early-exit control
  flow, `BIG = 1e30`, and the initial-assignment swap; the wrapper
  (`kmeans.rs`) preserves the `nstart == 1` draw, the
  `any(duplicated(centers))` re-sampling from `unique(x)` (R `==`
  semantics: `0.0 == -0.0`, `NaN` matches nothing), the strict `<` on
  `nstart` totals, and R's stop/warning texts.
- **Known deviation**: `tot.withinss` (and only it) can differ by 1 ulp —
  R's `sum()` accumulates in long double. The operator publishes labels
  only, and the `nstart` comparison uses bitwise per-cluster wss, so a
  different start can only be selected when the exact totals differ by less
  than one f64 rounding.
- `k == 1` is R's MacQueen path; every point lands in one cluster, which is
  decided without running it. Its `wss` is computed exactly rather than
  MacQueen's incremental way — labels are unaffected.
- Deviations by refusal (R computes garbage instead): non-finite
  measurements and incomplete projections are errors naming the cell; R's
  `acast(fill = NaN)` plus Hartigan–Wong on NaN yields `ifault` 1 or nonsense.
- `seed` unset (`"NULL"`) is R's `set.seed(NULL)`: unreproducible by design.
  Parity claims are made on numeric seeds only.

## The platform golden test

`tests/test.json` is the R operator's own `test1` — same input, same
properties (`centers = 2`, `seed = 42`), same expected outputs
(`test1_out_1..3.csv` from the R operator's `tests/`). The port reproduces
those labels bitwise (parity case `test1_k2_i10_s1_seed42`). Not yet run
through a Studio install-check (no live instance while building). At release
time the same caveat as the clusterx lane applies: `tercenctl operator
install` reads the repository-root manifest, which is the R operator's — see
the NOTE in `.github/workflows/kmeans-rust-release.yml`.

## Shapes to keep in mind

- `k > m`: R's `sample.int` error text. `k == m`: the engine's `ifault` 3
  error text. `k < 1`: same engine text (R gets there via the Fortran).
- `iter.max < 1`: R's `"'iter.max' must be positive"`. `nstart < 1`: refused
  (R dies with an opaque length-zero error here).
- Empty cluster at the initial assignment (`ifault` 1) and the
  quick-transfer limit (`ifault` 4) surface as R's texts; 4 is a warning
  with the fit returned, exactly like R.
- No panic path from user data: property parsing errors, chunk decoding
  errors, index checks against the factor schemas, and `i32`/`u32` bounds
  on the result write are all errors.

## Release rules

Same as every Rust operator here (`create-rust-operator` §9): bump the
version and the `container` pin in one commit, let CI go green, then tag
`kmeans-rust-X.Y.Z` — the pin and the tag are one change. No `latest` tag.
The release workflow pushes the image and verifies the pin matches the tag;
the tercenctl install-check cannot run for a subdirectory manifest yet (see
the workflow's NOTE for the deployer).
