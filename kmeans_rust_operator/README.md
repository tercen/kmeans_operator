# K-means (Rust)

Rust port of the Tercen [kmeans_operator](https://github.com/tercen/kmeans_operator)
(the R operator in this repository, which remains the reference and is
unchanged). Clusters the observations of a projected crosstab with
`stats::kmeans`'s default algorithm — **Hartigan–Wong**, exactly as R runs it.

## Projection (identical to the R operator)

| | |
|---|---|
| rows (`.ri`) | variables (channels, markers) — the dimensions |
| columns (`.ci`) | observations (cells, samples) — the points being clustered |
| y | measurement |
| colours | none |

Output: one `cluster` label (`cluster1` … `clusterK`, 1-based like R) per
observation column, joined on `Observation` (`.ci`).

## Properties

| property | default | meaning |
|---|---|---|
| `centers` | 10 | number of clusters |
| `iter.max` | 10 | maximum Hartigan–Wong iterations |
| `nstart` | 1 | number of random starts (best `sum(withinss)` wins) |
| `seed` | `NULL` | a number runs R's `set.seed(seed)` (reproducible); `NULL` is R's unreproducible time seed, here OS entropy |

## Parity

**Bitwise** against the R operator on identical seeded inputs: cluster
labels, centres and per-cluster within-sums to the last bit, on the fixtures
in `tests/parity/` (generated by the R reference — see that directory's
README). This required reproducing, not approximating:

- R's Mersenne–Twister, `set.seed`'s LCG scrambling and the rejection-sampler
  `sample.int` (the same surrogate the clusterx lane validated);
- the Hartigan–Wong Fortran (`KMNS`/`OPTRA`/`QTRAN`), statement for statement
  including its early-exit distance loops and arithmetic order;
- the R wrapper's initial-centre sampling: `sample.int(m, k)` over the data
  rows, re-sampled from the **distinct** rows when the draw contains
  duplicates, and the `nstart` selection on `sum(withinss)`.

The one documented deviation: `tot.withinss` (never published by the
operator) can sit 1 ulp from R's, because R's `sum()` accumulates in long
double.

## Memory: the crosstab is streamed, never materialised

R's operator loads the whole long-format cell table (`.ci`, `.ri`, `.y` —
24 B/cell plus R's per-element overhead) and then gathers it with
`reshape2::acast` into a dense matrix. This port **streams the cell table in
bounded chunks** (counted against `Schema.nRows`) and folds each chunk
straight into two dense buffers sized from the row/column factor schemas:
value sums (8 B/cell) and occurrence counts (4 B/cell). Nothing of the cell
table is ever held whole; after the mean the counts are freed and
Hartigan–Wong runs on the sums buffer itself.

Peak working memory ≈ **12 B/cell + one chunk**, plus the runtime
(`memory_model.json` books 2·10⁻⁵ MB/cell + 150 MB with headroom). Missing
cells (an incomplete projection) are refused with an explicit error — R fills
them with `NaN` and produces a meaningless clustering.

## Building and testing

```bash
cargo test                       # unit + parity (needs the fixtures in tests/parity/)
cargo build --release
docker build -t tercen/kmeans_rust_operator .
```

`tests/test.json` is the platform golden test (the R operator's own `test1`
fixture and expected outputs, which the port reproduces bitwise).

See [CLAUDE.md](kmeans_rust_operator/CLAUDE.md) for the maintenance guide.
